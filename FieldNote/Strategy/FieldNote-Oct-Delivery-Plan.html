Delivery plan · v2 · built on NEO

Live by 31 October — building on what we already have.

We're not starting from zero. NEO already does YouTube ingestion, quote-grounded extraction, a filtered feed and a working RAG chatbot. FieldNote is NEO, re-pointed to firsthand customer-support records, verified and graded, migrated onto AWS. That reuse is what makes the date possible.

Verdict — achievable but tight

Two demanding choices, together: migrate NEO to AWS now and enforce strict firsthand-CS scope. Each is the slower option on its axis, so 31 Oct is the aggressive end of a 4–6 week effort against ~4.5 weeks of calendar. We make it by running engineering and curation as parallel tracks and launching on a small verified corpus (~40–60 records), not volume — with a stack-fallback if the migration runs long.

What NEO gives us — and the delta

Keep the machinery. Add the moat. Move the stack.

NEO's plumbing (ingestion, extraction, feed, chatbot) was never the hard part — the moat is the firsthand curation, grading and verification that NEO doesn't yet do. So the real work is the differentiating work.

How we run it

Two parallel tracks.

TRACK A · ENGINEERING (1–2 devs)

NEO → AWS + the delta

Port NEO to AWS (Aurora + pgvector, Lambda ingestion, Bedrock chatbot). Add grading, SCRUB tool + verified badge, Models/ROI facets, role profile. Rebrand NEO → FieldNote.

TRACK B · CONTENT (1 curator)

Firsthand CS corpus

Build the firsthand customer-support source registry, run the gate, SCRUB to verified + graded. Target ~40–60 records. Quarantine NEO's off-scope content from the FieldNote library.

Why parallel matters

The tracks are independent — curation doesn't wait on the AWS migration, and vice versa. Run them together from day one or the date slips.

Migrate the core; let AWS do the heavy lifting.

If we start slipping, in order

  1. Stack fallback: if the AWS migration runs long, launch on NEO's current stack on/before 31 Oct and complete the AWS cutover in early Nov. Protects the date without abandoning AWS.
  2. Chatbot → grounded search first; add the conversational layer post-launch.
  3. Fewer records (~40 strong) rather than 60.
  4. Never cut the SCRUB — unverified records destroy the one thing FieldNote sells.
