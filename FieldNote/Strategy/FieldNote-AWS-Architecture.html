FieldNote on AWS.

Every component to run the decision-intelligence platform — source ingestion, evidence-graded AI, the decision-card store, briefs, billing and enterprise-grade trust — mapped to AWS services and staged so you build only what each phase needs.

Build order matters

The plan calls for a concierge pilot before software. Don't stand up this whole estate now — Phase 0 is a thin slice. The full diagram is where you land by the focused-product and scale phases. Primary region: ap-south-1 (Mumbai) for the India base; add US/EU regions per customer data-residency later.

The decision pipeline

Signal → graded card, with a human in the loop.

A Step Functions state machine orchestrates each development from raw source to published card. The human evidence-review step is a real pause — Step Functions holds a task token until an analyst approves in the portal, then resumes.

Cost posture

Favour scale-to-zero, usage-priced services early — Lambda, Aurora Serverless v2 (idles down), S3, SES, and pay-per-token Bedrock. Defer the always-on cost items — OpenSearch, NAT Gateway, ElastiCache — until real load justifies them. That keeps Phase 0–1 in the low hundreds, not thousands.

Before you provision

Three things to verify.

  • Bedrock model + region. Confirm the exact Claude model you want is available in ap-south-1; if not, run the AI layer in a region that has it (e.g. us-east-1/eu-*) and keep data stores in Mumbai, or use cross-region inference.
  • Serverless-first, not Kubernetes. Skip EKS at this stage — Lambda/App Runner/Fargate carry the load with far less ops. Add containers only where a long-running process needs it.
  • This is the production estate, not the pilot. The plan's decision gates come first. If the concierge pilot doesn't clear them, you never build most of this — which is the point of phasing.
